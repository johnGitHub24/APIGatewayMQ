📡 APIGatewayMQ

高併發交易系統 — Gateway → Kafka → 多副本 Engine → PostgreSQL

Java 21 Spring Boot 3 WebFlux Gateway Kafka Redis 限流 Prometheus

系統本質：限流入口 → 202 快速回應 → MQ 削峰 → Engine 風控成交 → 輪詢查結果

本頁使用 Mermaid.js 繪製互動架構圖，用瀏覽器直接開啟即可，無需額外安裝工具。

技術標籤說明

標籤是什麼在本專案做什麼
Java 21程式語言版本Gradle toolchain 鎖定 JDK 21；Docker 使用 Temurin 21 JRE
Spring Boot 3Java 應用框架自動配置、依賴注入、內嵌伺服器、Actuator 監控

核心名詞辭典

名詞白話解釋
削峰尖峰流量先丟進 Kafka 排隊，Engine 按能力慢慢消化，不會瞬間壓垮後端
冪等（Idempotent）同一請求重送多次，結果與送一次相同；靠 Idempotency-Key + DB UNIQUE 實現
Consumer GroupKafka 消費者群組；同組內多副本分攤 partition，每條訊息只被一個 consumer 處理
Partition Key決定訊息進哪個 partition；本專案用 symbol，保證同標的順序處理
Round-Robin輪流分配；Gateway 查詢代理輪流轉發至 engine-1、engine-2
固定窗口限流每 1 秒重置計數器；超過閾值回 429（非滑動窗口）
pollUrl202 回應中的查詢路徑，Client 輪詢直到訂單 FILLED / REJECTED
fail-openRedis 故障時限流器放行請求，避免全站因 Redis 掛掉而不可用

HTTP 狀態碼

狀態碼意義本專案何時出現
202 Accepted已接受、處理中Gateway 收到下單、已排進 Kafka
201 Created資源已建立完成Engine 直連下單（測試用，同步）
200 OK成功輪詢查到訂單、查持倉、PnL 等
429請求過多超過 Gateway 每秒限流閾值
409 Conflict資源衝突重複下單（冪等觸發 DuplicateCheckRule）
422無法處理風控規則拒絕下單

3. 非同步下單流程

sequenceDiagram participant C as Client participant G as Gateway participant K as Kafka participant E as Engine participant D as PostgreSQL C->>G: POST /orders + Idempotency-Key G-->>C: 202 Accepted + pollUrl G->>K: OrderCommandMessage (key=symbol) K->>E: consume E->>E: RiskEngine + ExecutionEngine E->>D: save order/trade/position C->>G: GET pollUrl G->>E: proxy E-->>C: 200 order FILLED

為什麼回 202 而不是 201？

狀態碼語意適用場景
201 Created資源已建立完成同步下單（Engine 直連），訂單已寫入 DB
202 Accepted已排隊、尚未完成Gateway 非同步下單，只保證已進 Kafka

Gateway 只負責接收並排隊，不等待 Engine 跑完風控+撮合+寫 DB。HTTP 連線馬上釋放，尖峰不會堵在 Gateway，實現削峰。

關鍵欄位說明

欄位 / Header說明
Idempotency-KeyHTTP Header，客戶端自訂唯一鍵；重送同一 key 不會重複建單
clientOrderId訂單業務唯一 ID，對應 DB client_order_id UNIQUE
commandId每筆 Kafka 訊息的 UUID，用於日誌追蹤
pollUrl202 回應中的查詢路徑，如 /api/v1/orders?clientOrderId=demo-001
symbol交易標的（如 BTCUSDT），同時是 Kafka partition key
side買賣方向：BUY / SELL

Topicorder.commands — 下單指令的訊息通道
Partition Keysymbol — 同標的進同一 partition，保證順序處理
Consumer Grouptrading-engine — engine-1、engine-2 同組分攤消費
ProducerGateway OrderCommandProducer（spring-kafka）

Kafka 名詞

名詞解釋

5. 查詢代理（Round-Robin）

EngineProxyController 將 GET / PATCH / POST fill 請求轉發至 gateway.engine-uris 清單中的 Engine 實例。Docker 部署時配置 engine-1 (:8081) 與 engine-2 (:8082)。

名詞解釋
代理（Proxy）Gateway 不自己查 DB，用 WebClient 轉發請求給 Engine
Round-RobinAtomicInteger 輪流選 engine-1、engine-2，平均分散讀取負載
WebClientSpring 非阻塞 HTTP Client，配合 WebFlux 使用
engine-urisapplication.yml / 環境變數 ENGINE_URI_1、ENGINE_URI_2 設定的 Engine 位址

為何寫入走 Kafka、讀取走代理？ 下單要削峰 → Kafka 緩衝；查詢要即時結果 → 直接 HTTP 代理到 Engine 查 DB。

6. Redis 限流

RateLimitWebFilter 使用固定窗口（1 秒），以客戶端 IP 為 key。超過 gateway.rate-limit-per-second 回 429。

名詞解釋
WebFilterWebFlux 請求過濾器，在進 Controller 之前執行
固定窗口每 1 秒重置計數（非滑動窗口）；實作簡單但窗口邊界可能有 burst
INCRRedis 原子遞增；key = gateway:rate:{clientIp}
EXPIRE第一次 INCR（count==1）時設 1 秒 TTL
Retry-After429 回應 Header，建議 1 秒後重試
fail-openRedis 掛了時 onErrorResume 放行，避免全站不可用
 
{"errorCode":"RATE_LIMIT_EXCEEDED","message":"Too many requests, retry later"}

限流閾值：本機預設 50 req/s；Docker 環境變數 GATEWAY_RATE_LIMIT=100。

  → Kafka topic: order.commands（key=symbol）
  → OrderCommandConsumer（@KafkaListener）

【讀取路徑 — 輪詢/查詢】
Client
  → EngineProxyController
  → EngineProxyService（WebClient Round-Robin）
  → Engine OrderLookupController / OrderController
  → JPA → PostgreSQL
